## 1. 這是什麼

給高中生用的**讀書計畫 PWA**。核心流程：

1. 拍課本目錄 → AI 認出章節結構
2. 選科目、範圍、截止日
3. 演算法把「每一節」排進未來幾週的每一天
4. 每天打勾完成，可看日曆／統計

**介面文字全部是繁體中文**，新增 UI 也要用繁中。

## 4. 排程演算法（`server/src/routes/schedule.js`）

進入點是 `POST /api/schedule/preview`，回傳 `{ blocks, check, unplaced }`。

### 4.1 名詞

| 詞 | 意思 |
|---|---|
| **節** | 一般項目，標題像「單元3｜節2｜範例+例題」。一天可以排很多個 |
| **純題目** | 標題結尾是「單元練習」或「歷屆試題」。規則嚴格，見下 |
| **壓軸 / 模考** | `final: true`。獨佔該科的一整天，排在該科所有一般項目之後 |
| **bucket** | 分組鍵 `${subject_id}|${start}|${end}|${onePerDay?1:0}` |

### 4.2 硬規則（**改程式時絕對不能破壞**）

1. **截止日是硬的** — 任何項目都不能被排到自己 `end` 之後，就算最後補位（last-resort fallback）也不行。
2. **模考獨佔** — 模考那天，同一科不能有任何其他東西。
3. **純題目不與「節」同日** — 同一科同一天，純題目和範例+例題不能混。
4. **純題目一天最多 2 份**（`ONE_CAP = 2`）— 理想是 1 份，範圍真的塞不下才退讓到 2，**永遠不會有第 3 份**。
5. **任務不遺失** — 送進去幾項，排出來就要幾項（排不下的要進 `unplaced` 並回報，不能默默吃掉）。
6. **總量正確** — blocks 數量 = items 數量。

規則 3、4 由 `exclusiveOk(date, w)`（schedule.js:171）把關，最後還有一道 final exclusivity repair 收尾。

### 4.3 `onePerDay` 是怎麼認出來的

前端有好幾條路徑會送 items 進來，其中「使用者自己在精靈裡標純題目」那條**不會帶 `onePerDay` 旗標**。所以伺服器在 schedule.js:69 用標題最後一段補判：

```js
const ONE_TAIL = /(單元練習|歷屆試題|歷屆|試題|練習|題目)$/;
```

**這行不能拿掉**，拿掉規則就整個失效（測試會抓到）。

### 4.4 大致流程

1. 建可排日期 `days`（扣掉今天以前、指定排除日、排除星期、既定行程太滿的日子）
2. 依 bucket 分組，算每科每個 bucket 要多少天
3. **min-max greedy** 分配天數（不是平均分，是讓最壞的一天盡量好）
4. **Bresenham 速率累加**決定哪幾天放，避免整章擠在同一天
5. **phase chaining**：純題目 / 模考排在該科一般項目之後
6. 一連串後處理：rebalance → gap-fix → 全域負載平衡 → 各科平均度 → bucket 日期正規化 → 最後的獨佔修復

### 4.5 回傳的 `check`

`check.tight` / `check.subjects`（含 `availDays` / `wantDays`）是給前端顯示「哪一科塞不下、要延長幾天」用的，改動時要一起維護。

## 5. 測試

```bash
cd server && npm test          # 26 項，node --test，沒有額外相依套件

# 只跑某一組（旗標要放在檔案之前，npm test -- 的寫法不會生效）
node --test --test-name-pattern="截止日" "test/**/*.test.mjs"
```

測試會自己 spawn 一台伺服器（隨機埠 + 暫存 SQLite），**不需要先啟動 server**，也不會動到 `data.sqlite` 或雲端資料庫。

六組：截止日(4)、模考獨佔(6)、純題目(5)、任務不遺失(4)、總量(4)、順序(3)。

### 這些測試是有鑑別力的

不是寫爽的。每一組都用**變異測試**驗過——故意把程式改壞，測試要真的紅：

| 把程式改壞成 | 哪一組會失敗 |
|---|---|
| 最後補位不先看截止日 | 截止日 ❌ |
| 壓軸保留天數用全域天數算（而非該科自己的天數） | 模考獨佔 ❌ |
| 拿掉 `ONE_TAIL` 標題推斷 | 純題目 ❌ |
| 允許純題目與範例同日 | 純題目 ❌ |

這四項對應四個**真的發生過**的 bug。改完 `schedule.js` 一定要跑過。

## 6. 踩過的坑（別再踩一次）

### 時區：本機解析 + UTC 輸出 = 差一天
```js
new Date('2026-08-08T00:00:00')   // 照「本機時區」解讀
  .toISOString().slice(0, 10)     // 照「UTC」輸出   ← 在 UTC+8 會變成前一天
```
Render 跑 UTC 所以正式站看不出來，但機器一設 `TZ=Asia/Taipei` 就會少排一天，範圍只有一天時甚至直接回「沒有可排的日期」。
**現在日期一律用 `server/src/util/date.js`（UTC 進、UTC 出）。**
`TZ=UTC` / `Asia/Taipei` / `America/New_York` 跑起來都要是 26/26。

### React：箭頭函式直接回傳 Promise 會被當成清理函式
```js
useEffect(() => { loadAtts(); }, [task.id]);   // 一定要包成 { }
```
寫成 `useEffect(() => loadAtts(), ...)` 的話 React 會把回傳的 Promise 當 cleanup，
關掉任務時 destroy() → 整頁掛掉「l is not a function」。見 `client/src/tt/Tasks.jsx:221`。

### EXIF 方向
iPhone 直拍的照片 Orientation=6，直接送給 AI 會看到側躺的目錄。
現在先用 `<img>` decode 再經 canvas 重新編碼才送出。

### 排程曾經出過的錯（都已修 + 有測試守著）
- 整章擠同一天 → phase chaining 每個 onePerDay 項目多留了 1 天尾巴。改成工作量比例 + min-max greedy。
- 某科排到自己截止日之後 → 最後補位忽略了項目自己的範圍。改成四層 `pick(ownWindow, keepExcl)`。
- 模考保留日跑到短範圍科目之外 → 保留天數是用全域 `days.length` 算的。改成用該科自己可用的天數。
